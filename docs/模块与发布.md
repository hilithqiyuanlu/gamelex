# 模块边界与 0.3.0 试用发布

面向已安装大气层、Ultrahand 和加载器的 NS1 用户。GameLex 独立安装，不修改 UH 主程序、加载器、全局快捷键或主题。本次没有将核心流程改成依赖电脑，也没有增加后台堆或加载器内存。

## 模块

| 部分 | 当前目录 | 边界 |
| --- | --- | --- |
| 浮层与平台交互 | `switch/overlay` | 绘制、手柄／触屏、UH 返回、截图透明时机 |
| 阅读与分组 | `core/include/gamelex` | 坐标分组、选择范围、原文选词、布局与有界缓存；不直接调用 UH |
| 后台 | `switch/sysmodule` | 截图、联网、4 MiB 堆、按请求编号处理；百度实现独立在 `baidu.cpp` |
| 通信与版本 | `switch/probe_common.hpp`、`core/include/gamelex/protocol.hpp` | 请求编号、启动轮次、心跳与协议核对 |
| 安装与发布 | `scripts` | 固定文件白名单、哈希检查、备份与可恢复卸载 |

本版是代码职责分离，不是运行时动态插件系统。后续替换 OCR 服务时应输出同一套带文本与归一化位置的分组输入，继续复用阅读逻辑；仍需测试实际字体与画面，不能只凭接口适配宣称识别质量相同。

## 配套检查

原生组件与打包脚本统一从 `release.hpp` 读取版本。后台心跳带版本和协议号，前台在发送工作前检查两者；后台也核对请求者版本。旧后台、只更新一个组件或协议不匹配时提示完整更新并重启，不继续提交识别／翻译。

协议检查不取代后台新鲜度检查。旧 SD 状态或未来时间仍按不可用处理；联网期间发布简短心跳，保留取消入口。暂不改变现有双槽消息方式。

## 打包

```sh
python3 scripts/check_host.py
python3 scripts/build_switch.py
python3 scripts/package.py
python3 scripts/package_source.py
python3 scripts/package_trial.py
```

对外只发 `dist/gamelex-0.3.0-trial.zip`。包内含 `sd/`、安装／卸载工具、试用说明、反馈模板、对应源码和校验值。单独的 `gamelex-0.3.0.zip` 仍是原开发安装包，不含后台自启标记。

试用包明确包含 GameLex 自己的 `boot2.flag`，使用与原设备一致的开机后台方式；首次安装、更新和卸载后均要求完整重启。没有将未验证的按需启动作为同学试用的唯一启动方式。

安装器只允许固定程序文件和许可证路径，不允许安装清单覆盖用户 `config.json`、UH 或其他浮层。源文件哈希不符时停止；覆盖前备份，复制失败恢复；发现符号链接或遗留安装临时文件时停止检查。卸载先备份并校验四个已知程序文件，再移出；失败恢复，用户配置与数据保留。

发布包只附空白配置示例，默认不保存截图；不包含开发者密钥、私人截图、运行消息、设备记录或 `HANDOFF.md`。打包时检查来源文件、对应源码内容及本机已知密钥值是否意外混入；校验失败不生成新试用包。检查不等于通用秘密扫描工具。

## 兼容与验证

本机流程替身、消息／安装测试和本机 HTTPS 检查只能证明相应逻辑路径；不证明 NS 原生输入、VI、TLS 或与其他模块的内存共存。UH／加载器或系统更新后，至少复验启动、干净截图、返回游戏、输入恢复、连续识别和取消恢复，再更新兼容记录。

0.3.0 仍为小范围试用，不是完整 MVP。优先收集 `试用反馈.md` 中的环境、游戏页面和具体错误，再决定兼容调整，不要求用户统一替换环境。
