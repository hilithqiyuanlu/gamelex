# 0.2.3-safe：停止自定义全屏绘图，恢复标准界面

用户反馈 0.2.2 打开 GameLex 后没有显示，随后快捷键也无法再次呼出。此次先读取 SD 再修改。源码和现场记录备份在 `.backups/stable-ui-20261019-225725/`。

## 现场证据与判断

- `overlay-render.log` 只有 `before_screen`，没有进入自定义 `draw()` 后应产生的 `first_frame`。
- 浮层可见状态已切换为 true，之后又变为 false，说明程序至少走过了显示/隐藏回调。
- 后台心跳持续到用户取卡前，最近没有新的 scan 请求；不能把此次无界面解释为百度返回慢。
- 实际给浮层的堆为 3,158,016 字节，不能直接把库的 4 MB 配置当作可分配堆。
- 原实现会在显示时先清屏并提交一帧，再进入循环获取下一缓冲。上一版改成单缓冲，现场现象高度吻合“首次提交后无法取得下一缓冲”。缺少设备线程栈，仍将此作为主要判断，不冒充已抓到阻塞栈。

依据现有接力文档的回退条件，停止扩展自定义全屏层，不继续试另一种全屏尺寸。

## 本轮改动

- 还原库的绘图尺寸、双缓冲、动画、触摸与焦点逻辑，只保留简体中文字形后备选择。工程不再定义 `GAMELEX_FULLSCREEN_CANVAS`。
- 使用标准 `OverlayFrame + List`。打开先显示菜单，不自动联网；词语列表每页 16 项，阅读内容每页 10 行，防止一次生成大量界面对象。
- 加入不联网自检，示例词语和译文共用真实的结果/阅读页面。主机检查确认每个示例词都有本地答案，避免自检误发收费查询。
- 英文原文、词语查询与中文整屏译文分开显示。返回保留原列表，根菜单 B 真正退出，正常 Ultrahand 等待下一快捷键。
- 记录 `overlay-safe.log`，在标准框架完成绘制后记录 `home_drawn` 等阶段，避免只记录初始化就误判界面正常。
- 现场旧日志包含 `curl initialization failed`。锁定的 Switch curl 后端初始化依赖 `ssl` 与 `csrng`；原权限表缺少 `csrng`。新增此权限，并分别记录服务初始化结果。
- 恢复被动 TLS 诊断：透出 curl 错误及系统证书校验结果，记录用户/网络时钟，不修改设备时间，不关闭证书或主机名验证，诊断文本去除密钥。
- 移除无效 OCR 自动重试，保留一次整屏翻译；旧请求不再发布覆盖新响应。

## 测试与交付边界

文本工具的主机检查共 50 项，包括词语拆分、换行、分页及示例覆盖；其中也保留了早期坐标工具检查。这些检查不运行 NS 绘图、输入或加载器，不能替代实机验证。

必须先在 NS 完成“打开主菜单 → 不联网自检 → 查词/译文 → B 退出 → 快捷键重新打开 Ultrahand”，再测真实截图和联网。若最小界面仍卡住，停止功能扩展，读取 `overlay-safe.log` 确认最后阶段；不要再次只凭编译成功发全屏实验包。

`HANDOFF.md` 保持原样；最新操作步骤见同目录 `实机测试.md`。
